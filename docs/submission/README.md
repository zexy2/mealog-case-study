# Submission appendix

This folder preserves the material produced during the original interview
exercise that started Mealog. It is kept for provenance and transparency, not as
the entry point to the project.

**Start with the root [README](../README.md) instead.** Nothing here is needed
to run, read, or evaluate the current code.

| File | What it is | Why it is kept |
| --- | --- | --- |
| `STATUS.md` | Generated, auto-derived delivery status for each interview deliverable | Shows which claims were repository-verifiable at the time and which needed operator confirmation |
| `walkthrough.md` | Timed recording script for a video walkthrough of the submission | Records the narrative and the evidence boundaries observed while recording |
| `comparison.md` | Bounded product comparison against a public competitor | The exercise asked for an explicit comparison; the boundary rules are still worth reading |
| `hitl_data_flywheel_loom_presentation_report.html` | Slide-style report on the human-in-the-loop design | Context for [docs/data_flywheel_and_hitl_architecture.md](../data_flywheel_and_hitl_architecture.md) |
| `AGENTS.md`, `AGENT_LOG.md`, `onboarding-prompt.md` | The multi-agent working contract used to build this repo | Documents how the project was actually built |
| `appendix/interview-notes.md` | Private notes from the exercise | Historical record only |

## What changed since the exercise

- The repository is no longer positioned as a submission package. It is a
  living project; the README describes the product, not a checklist.
- `LICENSE` now states explicitly that the MIT grant covers the original code
  and documentation only, and that third-party nutrition data is excluded.
- Third-party data provenance moved to [docs/licensing.md](../licensing.md).
- The video walkthrough and email deliverables are historical artefacts of the
  exercise and are not maintained.
